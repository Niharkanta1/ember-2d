# Architecture & Plan Review — November 2026

Full review with diagrams: https://claude.ai/artifact/AvJd2dWpFYKTFNpKKvSNK3
This file is a condensed record of that review. Later on 2026-11-25, Android, bullet-hell and visual-novel support were added, which raised the module count to 10 library modules plus 4 demos (see `adr/ADR-003-MODULES.md`); the review text below is kept as written. The revised documents in this folder (revision 2) implement it; decision numbers below match `TECHNICAL_DECISIONS.md`.

## Verdict
The direction was sound (Java, libGDX, optional genre modules, data-driven content, runtime separate from tools), but the plan was too large and too self-built for one developer: ~35 Gradle modules, 18 thin specs and 11 phases, with much of the work re-implementing what libGDX and its ecosystem already provide.

## Critical findings and resolutions
| # | Finding | Resolution |
| --- | --- | --- |
| C1 | Box2D is a poor default for platformer, shooter and RPG movement | Kinematic collision by default; Box2D optional (ADR-005, F-006, F-006B) |
| C2 | Banning libGDX types from public APIs means re-wrapping its math and graphics vocabulary | libGDX core types allowed; only Box2D, backend and file paths hidden (ADR-013) |
| C3 | ~35 modules is a team structure | 7 library modules + 3 demos; ArchUnit-enforced packages (ADR-003) |
| C4 | Build order caused rework (scenes before ECS, assets after rendering, first game in Phase 8) | Game-driven roadmap; platformer slice in Phase 2 (ADR-018, `ROADMAP.md`) |
| C5 | JavaFX editor was the largest, riskiest item | Tiled + in-game ImGui dev tools; editor deferred (ADR-009, F-018) |
| C6 | Specs too thin to be a source of truth | Spec status (Draft/Ready); just-in-time expansion; F-001, F-002, F-003, F-019 expanded |

## Other changes
- **Built-ins over rewrites (ADR-014):** `AssetManager`, Scene2D.ui, `ParticleEffect`, Tiled loader, gdx-ai.
- **Missing contracts added:** render interpolation, entity references, one event model, pixel-perfect `FrameBuffer` pipeline, text, hot reload, timers/tweens, settings store, scene preloading, world flags, save scope, AI hooks, packaging, logging.
- **Genre support:** shared `kit-common` (health, damage, triggers, pools) and `kit-topdown` (movement shared by shooter and RPG); engine never names genre concepts.
- **Inconsistencies fixed:** wrong architecture image (it showed an unrelated C++/SDL3 engine), `engine-api` vs `engine-physics-api`, app pause vs game pause, MVP end phase, templates folder clash, settings ownership, gamepad test timing.
- **Process:** spike tasks; approved task plans count as spec updates; Draft/Ready/Implemented spec status.
- **Deferred:** standalone editor, custom tilemap format, custom UI widgets, custom particles, five audio channels, positional audio, weapon switching/burst/hitscan, lighting.

## Risk register
| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| Engine built, no game shipped | High | High | Demo-driven phases; playable build at every gate |
| Editor consumes a year | High (old plan) | High | Tiled + ImGui; editor deferred |
| Platformer feel poor on Box2D | High (old plan) | Medium | Kinematic collision default |
| Over-abstraction of libGDX | Medium | High | ADR-013 |
| Coding agents invent behaviour from thin specs | High | Medium | Spec status + just-in-time expansion |
| Third-party library goes stale (imgui-java, blade-ink, gdx-ai) | Medium | Low | Each behind one small adapter |
| Box2D v3 bindings change while incubating | Medium | Low | Use v2 extension; Box2D optional |
| Scope creep | High | Medium | Defer list; new features need a demo that requires them |
