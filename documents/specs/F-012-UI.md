# F-012 — Game UI (Scene2D)

- Status: I-220 Ready: expanded and approved 2026-11-27 (see "UI layer, menus and HUD (I-220)")
- Phase: 3
- Module / package: `ember-core` / `ember.ui`
- Depends on: F-004, F-005, F-008
- Tasks: I-220, I-225
- Decision: ADR-014 (use Scene2D.ui)

## Goal
HUDs and menus built on libGDX Scene2D.ui with a project skin and small helpers, correctly layered and receiving input before gameplay.

## Scope
- One `Stage` per scene (or shared), drawn on the UI render layer.
- Project `Skin` loaded by asset ID; pixel-font friendly defaults.
- Input routing: the stage receives input first; when a menu is open, the `ui` input context is active (F-005).
- Helpers: menu builder (vertical button list with keyboard/gamepad focus navigation and touch), HUD widgets (bar, counter, icon+label), dialogue box widget with typewriter text (used by RPG and `kit-novel`), choice list, confirm dialog.
- Screen-space and virtual-resolution UI modes (project setting).
- Touch-friendly sizing (minimum hit target), UI scale setting and safe-area layout on Android (F-022). On-screen controls are UI widgets bound to input actions (F-022).

## Non-goals
- A custom widget toolkit or layout engine.
- A UI editor.

## Acceptance criteria
- Main menu and pause menu navigable by keyboard, mouse and touch (gamepad in Phase 6).
- HUD updates from game state without allocation per frame.
- UI draws above the world and blocks gameplay input while focused.
- UI does not depend on `ember-devtools`.

## UI layer, menus and HUD (I-220)
Status: Ready (expanded for I-220 and approved 2026-11-27; see "Decisions in I-220"). Built on libGDX Scene2D.ui (ADR-014), wrapped thinly.

**One UI per scene.**
- `Scene.ui()` returns the scene's `Ui`: a Scene2D `Stage` with a root `Table` that fills the UI area, created on first use and disposed when the scene exits (no cost for scenes without UI).
- Only the top scene's UI is drawn and receives input, like its world.
- **Drawing:** the engine draws it after the world image and before the debug panel and on-screen controls, so UI is above the game.
- **Updating:** the stage's `act` runs every frame on **real** time, so menus animate and respond while the game is paused.

**Resolution modes** (`EngineConfig.uiMode`):
- `VIRTUAL` (default):
  - The UI is laid out in virtual pixels (320 × 180 in the demo) and shown in exactly the same screen rectangle as the world, at the same whole-number scale.
  - Pixel fonts stay crisp, and one UI pixel is one game pixel.
  - In `PIXEL_PERFECT_FILL` it uses the same widened area.
- `SCREEN`: the UI is laid out in screen pixels divided by `EngineConfig.uiScale` (default 1), for smooth text at native resolution.
- A minimum touch size for menu items (in dp) comes with the safe areas in I-225. I-220 sizes menu items generously (at least 24 virtual px high).

**Input.**
- **Pointer:** the stage gets pointer events **before** the game. A click or touch that lands on a UI widget does not reach the game's actions or gestures; one that misses every widget does.
- **Keyboard:**
  - Menus are driven by **input actions**, not Scene2D keyboard focus, so bindings, contexts and gamepads (later) apply.
  - A menu reads `ui_nav` (up/down), `ui_confirm` and `ui_back` from the `ui` context.
  - Opening a menu pushes `ui` (gameplay input then reads as up, F-005), and closing it pops it.
- The demo's `input.json` adds `ui_confirm` (Enter, Space, Z).

**Skin.**
- **Built in code:** `UiSkins.pixel(font)` builds a complete pixel skin from any `BitmapFont`, with no files. Its drawables are generated from small pixmaps (managed, so they survive Android context loss): panel, button (up, over, down, focused, disabled), slider, progress bar, scroll pane.
  - Styles: `Label` (default, `title`, `dim`), `TextButton`, `ImageButton`, `Slider`, `ProgressBar`, `Window`, `ScrollPane`.
  - Colours come from a small `UiPalette` (dark panel, light text, accent) that games can change.
- **From files:** a manifest type `skin` (a libGDX skin `.json` with its `.atlas` next to it, loaded by libGDX's `SkinLoader`). `ui.setSkin(assets.get("skin.main", Skin.class))`.

**Widgets** (thin Scene2D subclasses):

| Widget | What it does |
| --- | --- |
| `MenuList` | A vertical list of text buttons with a focused item. `ui_nav` moves the focus (wrapping), `ui_confirm` activates, `ui_back` runs the back action. The mouse hovering an item focuses it, and a click or tap activates it. Items can be disabled. The focused item shows the `focused` drawable. |
| `HudCounter` | An optional icon and a number or time (`setValue(int)`, `setSeconds(float)` as m:ss). The label text changes only when the shown value changes, so an unchanged HUD allocates nothing per frame. |
| `HudBar` | A progress bar 0..1 (health, timers) with `setValue(float)`. |
| `ConfirmDialog` | A modal panel with a message and two choices (for example "Quit to menu?" Yes / No), driven by the same actions. |

- **Not in I-220:**
  - the dialogue box with typewriter text and the choice list: they arrive with their first user, the RPG and novel (Phase 5)
  - safe areas, UI scale setting, touch target minimums and on-screen controls as widgets (I-225)
  - settings persistence (I-230)
  - gamepad focus (Phase 6)

**Demo.**
- **Main menu** (a new first scene, `MenuScene`):
  - The title "Ember2D Platformer" in the pixel font, over the level's background tile, with the frog idling.
  - Buttons:
    - **Play** starts level 1 (`replace`)
    - **Settings** opens music and sound volume sliders (applied at once through `ctx.audio()`; saved in I-230)
    - **Quit** (desktop only; hidden on Android, where Back leaves the app)
- **HUD** in level 1: time (m:ss) top left and deaths top right, as `HudCounter`s.
- **Pause menu:**
  - `pause` (P, double tap, touch "II") and `menu` (Escape, Back, long press) open it, and the game pauses (the music too).
  - Buttons: **Resume**, **Restart level**, **Settings**, **Main menu** (with a `ConfirmDialog`).
  - It replaces the I-105 menu cursor.
- **Level complete:**
  - A results panel (time, deaths) with **Play again** and **Main menu**.
  - It replaces the world text and the automatic restart from I-170 (`Goal.restartSeconds` is removed).

## API sketch (I-220)
```java
package dev.ember2d.ui;
@PublicApi public enum UiMode { VIRTUAL, SCREEN }                 // EngineConfig.uiMode, plus float uiScale
@PublicApi public final class Ui {                                  // Scene.ui()
    public Stage stage(); public Table root(); public Skin skin(); public void setSkin(Skin skin);
    public float width(); public float height();                    // UI area in UI units
}
@PublicApi public final class UiPalette { public final Color panel, panelBorder, text, dim, accent, disabled; public static UiPalette standard(); }
@PublicApi public final class UiSkins { public static Skin pixel(BitmapFont font); public static Skin pixel(BitmapFont font, UiPalette p); }
@PublicApi public final class MenuList extends Table {
    public MenuList(Skin skin, Input input);
    public TextButton add(String label, Runnable action);
    public void setDisabled(int index, boolean disabled); public void focus(int index); public int focused();
    public void onBack(Runnable action);
}
@PublicApi public final class HudCounter extends Table {
    public HudCounter(Skin skin, Drawable iconOrNull);
    public void setValue(int value); public void setSeconds(float seconds);
}
@PublicApi public final class HudBar extends Widget { public HudBar(Skin skin); public void setValue(float zeroToOne); }
@PublicApi public final class ConfirmDialog {
    public static void show(Ui ui, Input input, String message, String yes, String no, Runnable onYes);
}
// ember.app: Scene.ui(); EmberGame acts, draws and routes input to the top scene's Ui; EngineConfig.uiMode / uiScale.
// assets: manifest type "skin" (Skin.class via libGDX SkinLoader).
```
`ember.ui` may use `ember.render` (ARCHITECTURE rule 3) for the shared viewport bounds, and `ember.input` for actions.

## Decisions in I-220
- **Settings use value items, not sliders.** `MenuList.addValue(label, get, set, min, max, step)` shows "Music  80". Left/right change it, and confirm or a click steps it up and wraps. This works the same with keys, mouse and touch, and reuses the menu's focus. The skin still has a `Slider` style for games that want one.
- **One menu reads input at a time.**
  - `Ui` keeps the menus on its stage in the order they were shown, and only the last one reads actions; a `ConfirmDialog` above a pause menu takes the keyboard until it closes.
  - Menus join and leave this list when they are added to or removed from the stage.
- **Held directions repeat** after 0.35 s, every 0.1 s, on real time.
- **`Ui.setSkin(skin, disposeWithUi)`:** the demo builds the pixel skin per scene from the shared `font.pixel` asset and lets the UI dispose it. The skin never owns or disposes the font.
- **Shared font fix (found on the emulator):** `TextRenderer` and `TextDraw` set the font's scale to world units while drawing world text. They now restore the scale and integer positions afterwards; before, UI labels using the same font drew at 1/16 size in the level. `TextRendererTest` covers it.
- **UI camera:** `UiViewport` sizes its camera when the layout changes, not only when drawing, so pointer hits are right before the first draw (found by the click test).
- **Input routing:** `EmberGame` installs an `InputMultiplexer`: a `UiInputRouter` to the top scene's stage, then the engine's input source. Root tables are `Touchable.childrenOnly`, so empty UI area passes touches to the game, and HUD widgets are not touchable.
- **`UiMode` layout** is in `EmberGame.layoutUi` (package-private, tested): `VIRTUAL` uses the renderer's `ScreenLayout` (same scale, same bars, the widened area in FILL mode); `SCREEN` uses the window divided by `uiScale`.
- **The dialogue box, typewriter text and choice list** stay for Phase 5, as planned.
- **Arrived in I-450:** `DialogueBox` (name plate, typewriter text, choices in the box) with the RPG demo; see F-017 "Decisions in I-450". `UiTest` covers typing, completing, advancing and choices.
- **Demo:**
  - The new first scene is `MenuScene`, over a tiled `tex.background` (the level background added as a texture).
  - `DemoScene` has the HUD (time and deaths, top left; the touch pause button stays at the top right), the pause menu and the results panel.
  - Both scenes pop the `ui` context and unpause when they exit.
  - `LevelSystem` no longer restarts the level or writes the goal text, and `Goal.restartSeconds` is removed.
  - `input.json` adds `ui_confirm` (Enter, Space, Z) and P to `ui_back` (P closes the pause menu). `TAP` is no longer bound to `ui_back` (taps belong to the UI now).
- **Checks:**
  - Emulator, R8 release: the main menu (no Quit on Android), Play, the HUD, pause by the touch button, Back to resume, Settings values, Back to the pause menu, and the Main menu confirmation with No focused were checked by screenshots.
  - The results panel was not reached on the device.
  - The on-screen joystick and buttons still show over menus; hiding them outside gameplay belongs to I-225.
