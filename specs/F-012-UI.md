# F-012 — Game UI (Scene2D)

- Status: Draft
- Phase: 3
- Module / package: `ember-core` / `ember.ui`
- Depends on: F-004, F-005, F-008
- Tasks: I-220, I-225
- Decision: ADR-014 (use Scene2D.ui)

## Goal
HUDs and menus built on libGDX Scene2D.ui with a project skin and small helpers, correctly layered and receiving input before gameplay.

## Scope
- One `Stage` per scene (or shared), drawn on the UI render layer.
- Project `Skin` loaded by asset ID; pixel-font friendly defaults.
- Input routing: the stage receives input first; when a menu is open, the `ui` input context is active (F-005).
- Helpers: menu builder (vertical button list with keyboard/gamepad focus navigation and touch), HUD widgets (bar, counter, icon+label), dialogue box widget with typewriter text (used by RPG and `kit-novel`), choice list, confirm dialog.
- Screen-space and virtual-resolution UI modes (project setting).
- Touch-friendly sizing (minimum hit target), UI scale setting and safe-area layout on Android (F-022). On-screen controls are UI widgets bound to input actions (F-022).

## Non-goals
- A custom widget toolkit or layout engine.
- A UI editor.

## Acceptance criteria
- Main menu and pause menu navigable by keyboard, mouse and touch (gamepad in Phase 6).
- HUD updates from game state without allocation per frame.
- UI draws above the world and blocks gameplay input while focused.
- UI does not depend on `ember-devtools`.
